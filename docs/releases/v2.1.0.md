# Starpi v2.1.0

Starpi is a knowledge assistant in the browser that shows how far each answer can be trusted. It
answers from your files and a shared knowledge base, cites every passage, compares every statement
of the answer with the passages it cites, and gives you a receipt that anyone can check against the
original files. This release lets you talk to it without sources as well, picks a model that fits
your device, runs on devices without WebGPU, and adds fast cloud models that need no key of your
own, whose answers are source-checked like every other model's.

**Try it:** [www.starpi.app](https://www.starpi.app): pick *NVIDIA NIM cloud* in the model menu,
switch between *Free chat* and *Verified source mode* in the message box, or click *Try with
sample files* and open the *Source check* and the *Receipt*. No account or API key needed.
**Use the checks in your app or CI:**
[`@starpi/core`](https://github.com/umutcantezgel-cpu/Starpi/tree/v2.1.0/packages/core#readme)

## Highlights

- **Free chat and verified source mode.** *Free chat* is a conversation without retrieval: earlier
  messages are kept, answers stream with Markdown and copyable code blocks, and an attached file is
  used as context. *Verified source mode* is Starpi as before: every statement is compared with the
  cited passages, and every answer with sources has a receipt. Free answers say that they were not
  checked; quick prompts, sample questions and questions about a knowledge-graph entity always run
  in source mode.
- **A model for every device, chosen by you.** One menu lists 13 WebGPU models in three tiers
  (from SmolLM2 360M for phones to Gemma 2 9B for strong GPUs), three processor models for browsers
  without WebGPU, the NVIDIA cloud models and the existing cloud assistant and own server. Starpi
  recommends one from the device's GPU and memory, never picks a large model by itself, and asks
  before any download.
- **Runs without WebGPU.** SmolLM2 135M and 360M and Qwen 2.5 0.5B run on the processor with
  Transformers.js and a self-hosted ONNX Runtime, under the same strict Content Security Policy,
  and keep working offline once stored.
- **NVIDIA NIM cloud, no key needed.** 13 models that NVIDIA offers as free endpoints (Nemotron
  3.5 Lightning by default, Nemotron 3 Super and Ultra, Kimi K3, GLM-5.3, GPT-OSS 20B, Llama 3.2
  Vision and more) answer through Starpi's server, which holds a pool of keys and moves a request
  to the next key when one is rate-limited or fails before the answer starts. In source mode their
  answers are checked and receipted on your device like any other.
- **Chat tools:** copy buttons on code blocks, export of a chat as Markdown or JSON, and deleting a
  single chat.

Checked by hand for this release:

- The proxy answered through the Vercel preview deployment with the key pool from the environment:
  model list, a streamed answer, 403 without an Origin, 405 for other methods; the same against the
  NVIDIA API through `npm run preview` locally, with no key in any log.
- All 13 models answered a streamed request on 2026-10-14; three listed free endpoints were left
  out (one timed out twice, one took 81 s to its first byte, one is gone).
- A processor model (SmolLM2 135M) loaded and streamed an answer in headless Chromium under the
  production CSP with no CSP violation, loaded again offline, stopped on request and was deleted
  with the model data.
- In headless Chromium against `npm run preview` with the real key pool, free chat with the
  default NVIDIA model streamed a Markdown answer with a code block that could be copied, and a
  question about the sample files in verified source mode got the source check and a
  `starpi.receipt/v2` receipt with `engine: "nvidia"`, without a CSP violation, console error or
  failed request.
- A review with six lenses (secrets and proxy abuse, the source check for the new engines, build and
  service worker, UI and accessibility, Python parity, privacy) found 21 issues. 19 were fixed (two
  of them, both about saving settings, by one change), among them bundle names that did not change
  with their content, keyboard steps that each switched the model, and privacy texts that did not
  mention the new destinations; regression tests cover the fixes in the stream parser, both
  proxies, keyboard use and quick prompts. One is documented: the Python backend applies its NVIDIA
  read timeout to each read (see the known limitations in `SECURITY.md`). One is open: Diagnostics
  starts a measurement only when WebGPU is available, so a processor (WASM) model cannot be
  measured on a device without WebGPU.

`npm audit --omit=dev` and `pip-audit` report no known vulnerabilities (2026-10-14). The full
`npm audit` still reports GHSA-vfj7-8cjw-p6xm (braces 3.0.3, no patched release) in the file
watcher of Tailwind CSS 3, development tooling that is not shipped in `dist/`. Both SBOMs pass the
CycloneDX 1.5 checks and are byte-identical across two runs. actionlint, zizmor (pedantic) and
gitleaks report nothing.

## Upgrade notes

- **Hosting on Vercel:** set `NVIDIA_API_KEYS` (comma-separated `nvapi-` keys, a sensitive variable
  for Production and Preview) before deploying; without it the NVIDIA models show as not set up.
  Optional: `NVIDIA_RATE_LIMIT_PER_MINUTE` (default 20 per address and instance) and
  `NVIDIA_ALLOWED_ORIGINS`. Read the NVIDIA section of `SECURITY.md` before using free keys on a
  public site.
- **Own backend:** the same routes are in `backend/server.py` (`NVIDIA_API_KEYS`); the browser calls
  them on its own origin, so serve the app and `/api/*/nvidia` from one origin (see
  `backend/README.md`).
- **Stored settings:** the on-device model preference of 2.0 (`qwen-3b`) becomes
  `webgpu:qwen-3b`; nothing else changes. First visits still start with the cloud assistant.
- **`@starpi/core`:** no API change.
- **Database:** no migration.
