# Starpi v3.0.0

Starpi is a knowledge assistant in the browser that shows how far each answer can be trusted. It
answers from your files and a shared knowledge base, cites every passage, compares every statement
with the passages it cites, and gives you a receipt that anyone can check against the original
files. Version 3.0 is a new generation: one AI layer for every major provider (with your key, the
site's free pools, your own server or a model on your device), a chat with branches, tools, voice,
Live and research jobs, chats and files that stay on your device, receipts signed on your device, a
source check that also compares relations, six interface languages, and Starpi's own local
companion for your machine.

**Try it:** [www.starpi.app](https://www.starpi.app): pick a free model in the model menu, switch
between *Auto*, *Free* and *Grounded* in the message box, or click *Try with sample files* and open
the *Source check* and the *Receipt*. No account or API key needed.
**Use the checks in your app or CI:**
[`@starpi/core`](https://github.com/umutcantezgel-cpu/Starpi/tree/v3.0.0/packages/core#readme) ·
**Run the companion:**
[`@starpi/companion`](https://github.com/umutcantezgel-cpu/Starpi/tree/v3.0.0/packages/companion#readme)

## Highlights

- **Every provider, one chat.** Anthropic, OpenAI, Gemini, xAI, Groq, Mistral, DeepSeek, OpenRouter
  and NVIDIA with your own key (direct, or through Starpi's stateless relay when a provider blocks
  browsers), free models from the site's key pools without any key, your own server, and WebGPU or
  processor models on your device. Keys stay in the tab, or encrypted in a passphrase vault.
- **A chat that keeps its word.** *Auto* decides per question whether your sources can answer it;
  *Grounded* answers are checked statement by statement and come with a receipt; *Free* answers are
  labelled as not checked. Branches, regenerate with another model, continue, attachments, tools
  with approvals, MCP servers with pinned tool definitions, canvas, compare and a council of models.
- **Voice that says only what was checked.** Dictation with a fallback chain of speech services,
  read-aloud through a sentence gate (a number is spoken only when its cited passage holds it), and
  Live conversations, free or from your sources.
- **Research jobs** that search your documents and the web in the background, survive a reload and
  write a report whose document part passed the sentence gate.
- **Source check version 3** compares changes, comparisons, order in time and carried-over values
  with the cited passages, in six languages; receipts (`starpi.receipt/v3`) are signed with a key of
  your device.
- **Your data stays with you.** Conversations and workspace files are kept on the device
  (IndexedDB and OPFS); sync is end-to-end encrypted and off until you turn it on; memory is off
  until you switch it on and keeps only what you choose.
- **Starpi Core, the local companion** (`@starpi/companion`): a loopback service with a sealed
  vault, a signed audit chain the browser checks for rollbacks, zero network egress by default,
  models routed by data class, and modules for search, notes, documents, checked answers, MCP,
  agenda, inbox and a local voice server. Paired with the app it becomes a source and a model of the
  chat.
- **Six interface languages:** English, German, French, Spanish, Italian and Turkish.

## Upgrading

A browser that ran 2.x moves its chats, remembered keys and settings on the first start of 3.0,
once. Operators, forks and users of `@starpi/core` find the breaking changes (generated headers with
cross-origin isolation, the removed Python service, receipts and source check version 3, new
reason codes) in the
[migration guide](https://github.com/umutcantezgel-cpu/Starpi/blob/v3.0.0/docs/MIGRATION-3.md), and
every change in the
[changelog](https://github.com/umutcantezgel-cpu/Starpi/blob/v3.0.0/CHANGELOG.md).

```bash
sha256sum -c --ignore-missing SHA256SUMS
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity https://github.com/umutcantezgel-cpu/Starpi/.github/workflows/release.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
gh attestation verify starpi-companion-3.0.0.tar.gz --repo umutcantezgel-cpu/Starpi

openssl pkeyutl -verify -pubin -inkey starpi-release.pub -rawin -in SHA256SUMS -sigfile SHA256SUMS.sig
```

## Before tagging

These checks need real keys, a deployment or real hardware, so they are done by hand before the tag
`v3.0.0` is pushed:

- [ ] **Providers with real keys.** `npm run providers:ping` for every provider and pool: that the
      relay passes browser calls for xAI, Groq, Mistral, DeepSeek, ElevenLabs and Tavily (CORS), that
      the free model ids of the pools still answer, and that the speech models
      (`SPEECH_MODELS` in `src/js/voice/catalog.js`) and the research model (`STARPI_RESEARCH_MODEL`,
      default `gemini-2.5-flash`) are still offered.
- [ ] **Relay rewrite on a Vercel preview.** The relay function must see the original
      `/api/relay/<provider>/<path>` URL after the rewrite of `vercel.json`. If it does not, switch
      the rewrite to `?provider=:provider&path=:path*` (which `relayTarget()` already accepts) and
      adapt `scripts/lib/routes.mjs`.
- [ ] **The preview end to end.** `crossOriginIsolated` is true, the headers equal
      `npm run headers:check`, a pool answer, a relay answer, read-aloud and dictation with the
      site's keys, a Gemini Live session with a real ephemeral token under the CSP, and a research
      job on the site's Gemini pool.
- [ ] **Supabase.** Apply the optional migrations `20261101000000_embedding_384.sql` and
      `20261102000000_chat_sync.sql` to the production project, run the RLS suite, put
      `{{ .Token }}` into the Magic Link and Change Email templates, then turn sync on in one browser
      and restore in another.
- [ ] **Release secrets.** `NPM_TOKEN` in the environment `npm` (the first publish of
      `@starpi/companion` needs it), optionally `STARPI_RELEASE_SIGNING_KEY` in the environment
      `release` with its public key published next to these notes.
- [ ] **Real devices.** A WebGPU model on a phone and a desktop, a processor model and semantic
      search with the multi-threaded ONNX Runtime the cross-origin isolated page allows, the
      benchmark on both runtimes.
- [ ] **The companion on real machines.** Install from the offline bundle as a Linux system unit
      (with the egress splice) and as a macOS launchd agent, pair in Mode A and from
      www.starpi.app in Mode B (Chrome asks for local network access), ask a question through the
      chat and check the audit banner after restoring an older backup.
- [ ] **Workflow lint and CI.** The `Workflow lint` job (actionlint, zizmor) passes on the release
      commit; actionlint and zizmor were not available in the container. Watch the end-to-end test
      `models.spec.mjs` "refuses to switch while an answer is being written", which failed once
      under heavy load and passed when run alone.
- [ ] **Date.** If the tag is pushed after 2026-10-19, update the date of this release in
      `CHANGELOG.md` and `CITATION.cff`.

## Known limitations

The most important ones are listed in the
[changelog](https://github.com/umutcantezgel-cpu/Starpi/blob/v3.0.0/CHANGELOG.md#known-limitations)
and, for security, in
[SECURITY.md](https://github.com/umutcantezgel-cpu/Starpi/blob/v3.0.0/SECURITY.md#known-limitations):
answers grounded by a search API carry no receipt, provider-side MCP runs allowed tools without
asking per call, the companion's egress guard runs in its process (only the Linux system unit adds
an outer boundary), computer control drives a simulated screen only, and `chat_sync` has no
per-user quota yet.
