# Starpi v1.1.0

Starpi is a knowledge assistant in the browser that shows how far each answer can be trusted. It
answers from your files and a shared knowledge base, cites every passage, compares every statement
of the answer with the passages it cites, and gives you a receipt that anyone can check against the
original files. Files are read on your device and never uploaded.

**Try it:** [www.starpi.app](https://www.starpi.app): click *Try with sample files*, ask a
suggested question, open the *Source check* and the *Receipt*. No account or API key needed.
**Tour of the code:** [docs/WALKTHROUGH.md](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.1.0/docs/WALKTHROUGH.md)

## Highlights

- **Source check on every answer.** Each statement is compared with the excerpts it cites:
  numbers in English and German formats, dates, times, weekdays, codes, quotations and wording,
  and names in English answers. A value that is not in the cited excerpt is named, the statement
  is highlighted and its citation marked; a value that stands next to something else in the
  excerpt is shown with its passage. Model answers are compared only with the part of each excerpt
  that reached the model. Deterministic, in the browser, no second model. On a held-out set of
  labelled answers it flagged all 49 changed values and no statement of a faithful answer as
  unsupported. It is an aid for reading the sources, not a proof: the panel says so.
- **Answer receipts.** A JSON file per answer with SHA-256 fingerprints of the source files, the
  offsets of each cited passage and the source-check verdicts. Verify it in the app or with
  `npm run verify:receipt`; the format is specified in
  [docs/spec/receipts.md](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.1.0/docs/spec/receipts.md).
  Receipts are not signed.
- **`@starpi/core`.** The source check, receipts, extraction, chunking and BM25 as a
  dependency-free ESM package with types and a `starpi-verify-receipt` command
  ([packages/core](https://github.com/umutcantezgel-cpu/Starpi/tree/v1.1.0/packages/core)).
- **Sample files in one click**, in English and German, and a prepared answer that shows the
  source check catching a wrong number.
- **On-device workspace.** PDF, Markdown, text, JSON and CSV files are parsed in a Web Worker,
  split into 500-character chunks with exact offsets and indexed with BM25; turns that use them are
  never synced or sent to a model as chat history.
- **Citations the model cannot forge.** Only labels the app registered become citation buttons,
  and the drawer highlights the exact span inside the source text.
- **WebGPU inference in a worker** with load sequencing, cancellation, quota and cache checks
  before any download, device-loss handling and a 32-bit fallback.
- **Accessible and bilingual.** English and German, keyboard-reachable everything, dialogs that
  keep focus, and an axe scan of every view in CI.
- **Hardened data access.** Anonymous Supabase sessions with owner-based row level security,
  read-only published rows, size limits on every browser-writable column, and a strict
  Content-Security-Policy without `unsafe-inline` or `unsafe-eval`.

## Upgrade notes

- **Database:** apply the files in `backend/supabase/migrations/` in file-name order
  (`20260923000000`, `20260924000000`, `20260924120000`) and enable **Anonymous sign-ins** in
  Supabase (Authentication › Sign In / Providers). Until then the app reads published knowledge and
  keeps chats on the device.
- **Node.js 22.13** or newer for development and builds.
- **Backend on EC2:** re-run `aws/deploy_ec2.sh`. The systemd unit no longer uses
  `EnvironmentFile`; the service reads `backend/.env` itself, and the file now belongs to the
  service user.
