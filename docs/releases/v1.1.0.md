# Starpi v1.1.0

Starpi is a local-first knowledge assistant that runs in the browser: drop PDF, Markdown, JSON or
CSV files, ask questions, and open every citation to the exact passage the answer was given. This
release adds the on-device workspace, verifiable citations, a worker-based WebGPU engine and an
English and German UI, and hardens the database, the browser and the backend.

**Try it:** [www.starpi.app](https://www.starpi.app) · **Tour of the code:**
[docs/WALKTHROUGH.md](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.1.0/docs/WALKTHROUGH.md)

## Highlights

- **On-device workspace.** Files are parsed in a dedicated Web Worker (pdf.js 6, which has no
  `eval`), split into 500-character chunks with a 50-character overlap and exact offsets, and
  indexed with Okapi BM25 in worker memory. Files are never uploaded.
- **Citations the model cannot forge.** Every passage carries a `[Doc: <name>, Chunk: <n>]` label.
  Only labels the app registered become citation buttons, and the drawer highlights the exact
  span inside the source text.
- **WebGPU inference in a worker.** WebLLM runs off the main thread with load sequencing,
  cancellation, storage-quota checks, device-loss handling and a 32-bit fallback. The Diagnostics
  tab measures time to first token and decode speed on the loaded model.
- **Clear privacy model per mode.** In the on-device mode the question stays in the browser; the
  footer states where the question goes in every other mode. Chat turns that use the workspace
  are never synced.
- **Hardened data access.** Anonymous Supabase sessions with owner-based row level security,
  read-only published rows, size limits on every browser-writable column, and no SECURITY DEFINER
  function callable from the browser.
- **Strict browser security.** A Content-Security-Policy without `unsafe-inline` or `unsafe-eval`
  (only `wasm-unsafe-eval`, which WebGPU inference needs), DOMPurify on all rendered Markdown, and
  provider keys kept in the tab unless the user opts in.
- **English and German.** English by default, switch instantly without a reload.

## Quality

| Suite | Scope |
| --- | --- |
| 107 unit tests | chunking offsets, BM25 scoring, parsing, prompts, retrieval, citations, i18n key parity, icons, documentation |
| 15 end-to-end scenarios × 2 viewports | production headers and CSP, inert XSS payloads, workspace privacy, citations, offline reconnect, settings storage, language switch |
| 83 backend tests | request guards, body limits, timeouts, shutdown, `.env` parsing, pipelines |
| 184 database assertions per scenario (191 with legacy rows) | RLS isolation, privileges, RPCs and size limits on PostgreSQL 16 with pgvector |
| Documentation | every Mermaid diagram renders, copies match the atlas, links and anchors resolve |

`npm audit` reports no known vulnerabilities (2026-09-24). CI runs all suites plus secret scanning
on every push and pull request to `main`.

## Upgrade notes

- **Database:** apply `backend/supabase/migrations/20260923000000_harden_rls_anonymous_auth.sql`,
  then `20260924000000_lock_published_rows.sql`, and enable **Anonymous sign-ins** in Supabase
  (Authentication → Sign In / Providers). Until then the app keeps chats on the device.
- **Backend on EC2:** re-run `aws/deploy_ec2.sh`. The systemd unit no longer uses
  `EnvironmentFile`; the service reads `backend/.env` itself, and the file now belongs to the
  service user.
