# Starpi v1.3.0

Starpi is a knowledge assistant in the browser that shows how far each answer can be trusted. It
answers from your files and a shared knowledge base, cites every passage, compares every statement
of the answer with the passages it cites, and gives you a receipt that anyone can check against the
original files. This release makes those checks available to other applications: `@starpi/core`
is ready for npm, and every release now carries the package tarball, CycloneDX SBOMs and checksums,
built by CI without write access.

**Try it:** [www.starpi.app](https://www.starpi.app): click *Try with sample files*, ask a
suggested question, open the *Source check* and the *Receipt*. No account or API key needed.
**Use the checks in your app:**
[`@starpi/core`](https://github.com/umutcantezgel-cpu/Starpi/tree/v1.3.0/packages/core#readme)

## Highlights

- **`@starpi/core` 1.3.0, the first release for npm.** The source check, answer receipts, text
  extraction, chunking and BM25 as one ESM package with type declarations, no dependencies and a
  `starpi-verify-receipt` command. It now has the app's version and is released with it. Install it
  with `npm install @starpi/core`, or from the tarball attached to this release (check it with
  `sha256sum -c --ignore-missing SHA256SUMS`); the npm package is published from that tarball. The
  [package README](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.3.0/packages/core/README.md)
  has an example for every task, each run against the packed tarball.
- **Release assets built without write access.** A read-only job packs the package from the commit
  CI tested, installs it offline into an empty project, imports it and runs its command, then
  writes `SHA256SUMS`. The job that creates the release installs and runs nothing from the
  repository and checks the checksums before it attaches `starpi-core-1.3.0.tgz`,
  `starpi-1.3.0.cdx.json`, `starpi-core-1.3.0.cdx.json` and `SHA256SUMS`.
- **CycloneDX SBOMs.** `npm run sbom` writes CycloneDX 1.5 SBOMs of the app and of the package
  from the lockfile, byte-identical for one commit and one npm version, and checks them before
  writing. CI uploads them on every run; this release carries them. The package's SBOM lists no
  other component, because there is none.
- **Every pull request packs the package**: CI runs the typed build and lists the published files,
  so a broken type declaration fails a pull request, not a release.
- **Supply chain documented.** A
  [Supply chain](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.3.0/SECURITY.md#supply-chain)
  section in the security policy (SBOMs, audit gates, pins, release assets and how to verify
  them), supported versions for the package, and a
  [release process](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.3.0/CONTRIBUTING.md#releases)
  in the contributing guide.
- **Dependency audit in CI**, added since 1.2.0: any advisory in a runtime npm dependency or in the
  backend requirements fails CI; advisories in development tooling are reported.
- **Ecosystem.** The first downstream project, Fluid Systems (a local assistant for production
  management in plastics processing, at demo stage), is built on Starpi's source check, receipts,
  extraction, chunking and BM25; see
  [Ecosystem and downstream use](https://github.com/umutcantezgel-cpu/Starpi/blob/v1.3.0/README.md#ecosystem-and-downstream-use).

Checked by hand for this release: the packed tarball installs offline, every example in the package
README runs against it, and it type-checks in a strict TypeScript consumer; both SBOMs pass the
CycloneDX 1.5 JSON schema, and the app SBOM lists 380 components (379 npm packages and the
workspace), development tooling marked. On every release, CI installs the tarball offline and
runs its exports and command before anything is published.

`npm audit --omit=dev` and `pip-audit` report no known vulnerabilities (2026-10-13). The full
`npm audit` reports GHSA-vfj7-8cjw-p6xm (braces 3.0.3, no patched release yet) in the file watcher
and glob matching of Tailwind CSS 3, development tooling that only expands the globs of
`tailwind.config.js` and is not shipped in `dist/`. CI runs all suites plus secret scanning on
every push and pull request to `main`; releases are created by CI from these notes.

## Upgrade notes

- **`@starpi/core`:** 0.1.0 was never published; 1.3.0 is the first npm release. The API is the
  one of 0.1.0. PDF extraction still needs the optional peer `pdfjs-dist` 6.
- **Development:** the root `package.json` declares `packages/core` as a workspace; run `npm ci`
  after pulling, which links it as `node_modules/@starpi/core`. `npm run sbom` writes the SBOMs
  into `sbom/` (ignored by git).
- **Database and backend:** no migration and no change to the backend code or its runtime
  requirements; reinstall `backend/requirements-dev.txt` for ruff 0.16.10 and pip-audit 2.10.1.
